# Bench: "S1-mini" by "Superwhisper" vs Qwen3-1.7B edit lists for cleanup (2026-11-11)

> **Archived.** Measured the S1-mini rewrite aligned into validated edits, an engine that is gone; current cleanup measurements: [2026-11-13-cleanup-fidelity.md](../../bench/2026-11-13-cleanup-fidelity.md). Why S1-mini is the default model still stands.

> **Small sets.** 44 handwritten cases (as in [the Qwen3 bench](2026-11-11-cleanup.md)) plus 29 real dictations
> from one live-testing session. One case moves exact match by 2–3 points. These are smoke and regression sets,
> not accuracy estimates.

## Why

Live testing with Qwen3-1.7B (edit-list engine) returned `no_edits` for 15 of 17 real dictations: fillers
(`um`, `uh`, `like`, `you know`, `basically`) and the self-correction `Run the tests on Tuesday, no wait on
Wednesday.` all survived. It also damaged Czech: `Tohle je test diktování v češtině.` came back title-cased.

[S1-mini](https://huggingface.co/superwhisper/s1-mini) is a Qwen3-0.6B fine-tune that normalizes ASR output. It
removes fillers, resolves self-corrections and writes numbers as digits. It returns the full rewritten text, not
edits.

### Control line

I ran all 73 inputs through S1 with each styling. On the 34 inputs that are already clean, the raw rewrite
changed:

| styling | changed | how |
|---|---|---|
| **semi-formal** | 10/34 | final periods and commas, `!` → `.`, quotes around a mentioned word, ASR-error "fixes" (`Qan II` → `QANII`, `commit-m` → `commit`). The validator rejects all but the plain punctuation. |
| semi-casual | 32/34 | lowercases sentence starts and drops final periods, which damages already-cased ASR output |
| casual | 32/34 | as above, and also strips apostrophes |

Parakeet output arrives cased and punctuated, so every profile uses `semi-formal`. Chat keeps its "no added
final period" rule: the server removes a final `.` that S1 added to a chat text without end punctuation.
`lists` and `email` are not used yet.

## S1 engine: rewrite → edits → validator

1. Tokens are split on whitespace and aligned with `difflib.SequenceMatcher` on their words, ignoring case and
   punctuation.
2. Each changed stretch becomes a quoted edit. A deletion or insertion takes a neighbouring token along. A quote
   that is not unique grows by one token on each side. A stretch that contains a correction cue grows until it
   has the self-correction shape (kept words + 1–8 retracted words + cue + correction). Overlapping stretches
   merge.
3. The edits go through the existing validator (`resolve_edits`). The kind is whichever invariant the edit
   passes. The validator also checks protected spans and the global rules.
4. **All or nothing:** if one edit is rejected, the raw text is kept. The client validator checks the result again.

Validator changes (server and client):
- `number_format` is now checked: spoken numbers must become digits with the same value.
- `filler_removal` also allows `like`, `basically`, `literally`, `you know`, `kind of`, `sort of` and immediate
  repeats (`the the`).
- Punctuation edits may only add or remove `. , ; : ? ! ' ’ -`, and the result may not lose a `!`.
- Fillers may make up at most half of the words.
- A self-correction may drop protected spans inside the words it retracts.
- An edit may overlap a protected span only if the span text survives unchanged: `main.py` → `main.py.` passes,
  `3:30 pm` → `3:30pm` does not. A negation may only be re-cased at a sentence start.
- The client validator now checks self-corrections and number formats. It used to reject them.

The Qwen3 baseline exposed two holes in the first version of these changes, and both are now closed:
`There is no wait` → `There is No wait` was accepted, and so was `I mean it, this…` → `It, this…` (`I mean` as a
filler). S1 triggered neither.

## Remaining S1 failures

- **All-or-nothing loses long dictations.** S1 handled both long real texts well, but each contained one change
  the validator cannot verify: deleting `I don't know` (a negation), `super whispered` → `Superwhisper`, or
  `like if um Hark could do` → `like Hark to do`. So the raw text was kept, fillers included. Applying only the
  edits that pass would recover most of the cleanup. Each such edit is safe by itself, but the result would mix
  S1's output with the raw text. That is not implemented.
- `No freaking way` → `No, freaking way`: a comma after a sentence-initial `No`. It passes every mechanical check.
- `3:30 pm` → `3:30pm` and `docker` → `Docker` touch protected spans, so the whole rewrite is dropped and the
  sentence-start capitalization is lost with it.
- Quotes around mentioned words (`delete the word "not"`) are rejected, by design.
- Garbled ASR (`So what um can I say them like foot wait what?`): S1 restructures it, the rewrite is rejected
  and the raw text stays. This is acceptable.

## Decision

**Default: S1-mini (`s1-mini-q4_k_m`, engine `s1`).** On the 44 cases it scores +11 exact over the 1.7B, with
8/8 self-corrections and 0 damage. It is 4× faster (p95 78 ms vs 331 ms) and 2.3× smaller (484 MB vs 1.1 GB).
It is the only model of the two that removes real fillers. `--cleanup-engine edits` (TOML `cleanup.engine`) keeps
the Qwen3 engine. `scripts/poc-up` picks the engine from the model key.

License: Apache 2.0 plus an additional term: the model must be identified as "S1-mini" by "Superwhisper".
hark does not redistribute the weights. `scripts/fetch-models` downloads them pinned and keeps the `LICENSE` and
`NOTICE` next to them (`models/s1-mini-q4_k_m.{LICENSE,NOTICE}`). The docs use that name.

## Update 2026-11-12: per-edit acceptance

This replaces step 4 of the S1 engine ("all or nothing") and closes the first remaining failure above. The server
and the client validator now accept edits per group:

- Edits at most one word apart form a group (transitively). An edit that fails a per-edit check (quote, range,
  protected span, kind invariant) is dropped with its group, so dropping `step, uh,` → `step.` also drops
  `can` → `Can`. The other edits are kept as `DEPENDENT` rejections. An edit that overlaps an accepted one is dropped
  alone.
- The global rules run on the accepted edits. A negation, digit or `!` change is pinned on the edits that make
  it. Their groups are dropped and the rules run again. Any other failure (changed bytes, removed words, sloppy
  result) keeps the raw text.
- For S1 the >50% invalid rule is off: a rewrite changes words that no check can verify. More than `max_edits`
  accepted edits still keeps the raw text.
- Client status is `applied`, `partial` (the reason gives the counts) or `rejected`. `cleanup.dropped` in the
  history lists each dropped edit with its reason and the side that dropped it.

Same setup: one S1-mini q4_k_m llama-server on port 8095, alone; the user's servers ran alongside. Two runs per set
gave identical outputs.

|---|---|---|---|---|
| exact | 40 | **43** | 25 | **26** |
| same words | 42 | **44** | 26 | **27** |
| clean damage | 0/12 | 0/12 | 1/22 | 1/22 (same `No,` case) |
| protected leaked | 0 | 0 | 0 | 0 |

Gains: `the meeting…` gets its capital, and `3:30 pm` stays unchanged. `um, why does npm ci…` loses the `um`;
`docker` and its neighbour `image?` are dropped. In `t-inject-3` the `um` is removed and the sentence start is
capitalized; the quoted `"not"` and its neighbours are dropped. In `So what um can I say…` only `um` is removed.
None of the cases got worse.

The two long dictations still miss the exact expected text, but they now get most of the cleanup:

- `r-filler-1`: `that uh` → `that` and `I mean,` are applied. `different uh I don't know like` → `different`
  (protected negation) is dropped, so the `uh` and `like` in that stretch stay.
- `r-filler-5`: 6 of 14 edits are applied: `and like`, `you know`, `not uh` and `the like` are removed, and
  `HARK`/`hark` → `Hark`. These are dropped: `like if um` → `like` and `could` → `to` (rewording), `do like` (in
  their group), `etc etc`, `we I don't know we we I` (negation), `super whispered` → `Superwhisper` and
  `previous the`.

Both rewrites are fixtures in `server/tests/test_cleanup.py`.

## Update 2026-11-12: correction cues and merges into known terms

Two real dictations from live testing lost a correct S1 edit to `protected_span`:

- `I want it written in C, uh no, in Rust.`: S1 removed `in C, uh no, in` → `in` (Superwhisper gives the same
  `I want it written in Rust.`). A bare `no` was not a cue, so the `no` stayed a protected negation.
- `Super Whisper` → `Superwhisper`: `Super` and `Whisper` were protected bias terms (in another dictation, with no
  protection, the same merge failed every invariant).

Validator changes (server and client, rules in `server/README.md`):

- **Bare cues** `no`, `sorry`, `actually` (plus the new phrase cue `make that`) count as cues only when they are set
  off by punctuation on both sides and the correction has the same shape as the retracted words: it repeats their
  first word (`in C, uh no, in Rust`) or replaces one word after a kept word (`on Tuesday, no, Wednesday`). Fillers
  may surround any cue. For every cue: 1–6 retracted words (was 1–8; fillers not counted), no sentence end inside
  them, no `?`/`!` next to the cue, and a `.` next to it only for a restart (`My name is David. Uh no, my name is
  Dan.`). Inside a valid correction, the retracted words and the cue may drop protected spans. Everywhere else
  `no` stays a protected negation: `No, I don't want C.`, `Is it done? No, it is not.`, `use C not Rust`,
  `there is no wait time`.
- **Merges into known terms**: a `spacing` edit may merge or split words and re-case them if the result is exactly a
  known term. Known terms are the new `CleanupRequest.known_terms` (the client sends its shortlist canonicals) and
  the text of protected spans that are not numbers or negations. Protected spans inside the merged words may change.
  Without the term, the merge stays rejected.

servers ran alongside, and the load average was 6–10, so latency is not comparable between runs. Generation time is
all but ~2 ms of it in both runs. The new `cleanup_eval_guard.jsonl` set has 9 cases: 2 real dictations, the real
`Super Whisper` dictation with the terms `Super`, `Whisper` and `Superwhisper`, 3 bare-cue corrections and 3
negations that must not change.
