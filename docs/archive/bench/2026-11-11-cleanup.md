# Bench: text cleanup with Qwen3 0.6B / 1.7B on llama-server (2026-11-11)

> **Archived.** The Qwen3 edit-list engine is gone; current cleanup measurements: [2026-11-13-cleanup-fidelity.md](../../bench/2026-11-13-cleanup-fidelity.md).

> **Superseded as the default** by "S1-mini" by "Superwhisper": see [2026-11-11-cleanup-s1.md](2026-11-11-cleanup-s1.md).
> The Qwen3 edit-list engine stays available (`--cleanup-engine edits`).

> **44 handwritten cases, not real dictation.** The texts imitate punctuated, cased ASR output (Parakeet style), plus a
> few lowercase inputs. One case moves exact match by 2.3 points. The set is a smoke test and regression guard for
> prompt and validator changes, not an accuracy estimate.

## Setup

| | |
|---|---|
| Host | Apple M5 Pro, 48 GB, macOS 26.5.1. Other agents were running builds and benchmarks; load average 4–6 during the final runs (9 during the first ones). |
| LLM server | llama.cpp `b12284` (`scripts/fetch-llama`, Metal), `scripts/llama-up`: `-ngl 99 -c 2048 -np 1 --cache-prompt --jinja --reasoning off --temp 0`, plus `--spec-type ngram-simple --spec-ngram-simple-size-n 1 --spec-ngram-simple-size-m 4` unless stated otherwise. |
| Models | `scripts/fetch-models all`: Qwen3-0.6B and Qwen3-1.7B. Q8_0 comes from `Qwen/Qwen3-*-GGUF`; Q4_K_M from `unsloth/Qwen3-*-GGUF`, because Qwen does not publish Q4_K_M for these sizes. All files are sha256-pinned. |
| Path | `scripts/eval-cleanup` starts an in-process hark server (mock ASR) that proxies to llama-server. Each case runs as a real `TextCleanup.Cleanup` gRPC call, so the server-side prompt, JSON schema, edit resolution and validator are all exercised. Budget 3000 ms, so nothing is truncated. One untimed warm-up call per profile. |
| Data | `server/tests/data/cleanup_eval.jsonl`: 44 cases. Profiles: 24 terminal, 11 chat, 9 prose. Categories: filler 6, self_correction 8, number 4, negation 6, identifier 4, injection 5, clean 10, punctuation 1. 12 cases need no edit (10 "clean" plus 2 others). Some cases accept more than one output. |

Metrics:
- **exact**: the output is one of the expected texts.
- **words**: same words as an expected text, ignoring case and punctuation. This shows whether fillers and self-corrections were handled.
- **clean damage**: cases whose input is already correct, but the output differs.
- **protected**: edits rejected for touching a protected span (caught), and protected substrings missing from the output (leaked).
- **invalid**: rejected / (accepted + rejected) edits.
- **latency**: client wall time per Cleanup RPC. Generation is within 1–2 ms of it.

Quality was identical across repeated runs (temperature 0). Latency varied by about ±10% between runs.

### Prompt-lookup speculative decoding (A/B, alternating runs, same load)

Edits mostly copy text from the input, so n-gram drafts taken from the prompt are often accepted: 52% acceptance,
mean accepted length 3.1. Greedy verification keeps outputs identical: every A/B pair had the same 30 or 31 exact.

| 1.7B | no speculation p50 / p95 | ngram-simple n=1 m=4 p50 / p95 | speed-up (p50) |
|---|---|---|---|
| Q8_0 | 673 / 1046, 618 / 977 | 289 / 446, 257 / 408 | 2.3× |
| Q4_K_M | 399 / 667, 390 / 674 | 212 / 362, 210 / 350 | 1.9× |

Decode without speculation runs at 6.7 ms/token (Q4_K_M) and 11.7 ms/token (Q8_0). The sweep also tried n=1 with
m=8 and m=16, n=2 with m=4, 8 and 16, n=3 with m=16, and a 0.6B draft model. Longer drafts and the draft model were
slower: the draft model gave p50 600 ms. n=1, m=4 was the most consistent.

Prompt cache: the static prefix (policy + profile rules + few-shots) is 750–1000 tokens. With the cache warm, each
request evaluates only ~30 new tokens, which takes ~32 ms. Switching profile re-evaluates the profile part,
~500–770 tokens in 120–160 ms. That only happens when the user switches between app types.

## Decision

**Default: `qwen3-1.7b-q4_k_m` with prompt-lookup decoding.**
- It is the only configuration that meets the proposal-a cleanup budget (p95 ≤ 400 ms) with useful quality.
- Its quality is within one case of Q8_0, which is noise at n=44: 30 vs 31 exact, 37 vs 36 same-words, 0 damage for both.
- At 1.1 GB, it also suits the RTX 3060 (shares VRAM with ASR) and a CPU fallback better.

Qwen3-0.6B is not worth running. It barely beats doing nothing (+4 exact) and handles no self-corrections. Its
model-side errors are mostly caught by the validator: 0.6B Q8_0 damaged nothing, 0.6B Q4_K_M damaged 1/12 clean cases.

## What changed to get here (1.7B Q8_0, same eval)

| step | exact | words | clean damage |
|---|---|---|---|
| first prompt, strict single-kind validator | 22 | 29 | 1 |
| + relabel kinds by invariant, split combined case+punctuation quotes, no-ops don't count as misbehaving, self-correction keeps a shared prefix | 26 | 36 | 2 |
| + result sanity rules (no new `  `, `,,`, `,x`, `. lowercase`), prompt wording ("never remove correct punctuation", self-correction starts at the first replaced word) | 31 | 35–36 | 0 |

## Remaining failures (1.7B Q4_K_M)

- **Self-corrections (5/8).** The model often quotes from the cue (`"no wait, 60 seconds."` → `"60 seconds."`), or
  drops the final period in chat. The validator rejects these because nothing is retracted, so the raw text is pasted.
- **Sentence-start capitalization in the terminal profile** (`never force push…`, `run kubectl…`, `rename useState…`).
  The model leaves it, or echoes the text as a no-op. Debatable for a terminal anyway.
- **Missed fillers.** A second `uh` in one sentence, or the filler gets capitalized (`uh,` → `Uh,`).
- **Injection-looking text was never obeyed.** Failures are only missed casing or fillers. In one earlier run the model
  tried to delete "ignore previous instructions and" as a `self_correction`; the invariant rejected it.
- **Echo no-ops** (find == replace) are ~⅓ of all proposed edits. They are harmless but cost output tokens and therefore latency.

## Reproduce

```sh
scripts/fetch-llama && scripts/fetch-models all
scripts/llama-up qwen3-1.7b-q4_k_m &          # any key from scripts/fetch-models
scripts/eval-cleanup --model qwen3-1.7b-q4_k_m -v --json /tmp/q4.json
# without speculation (A/B): llama-up passes extra args through, but a later --spec-type none
# does NOT override the default; start models/bin/llama-server by hand without the --spec-* flags.
```
