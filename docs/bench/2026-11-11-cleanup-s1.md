# Bench: "S1-mini" by "Superwhisper" vs Qwen3-1.7B edit lists for cleanup (2026-11-11)

> **Small sets.** 44 handwritten cases (as in [the Qwen3 bench](2026-11-11-cleanup.md)) plus 29 real dictations
> from one live-testing session. One case moves exact match by 2–3 points. These are smoke and regression sets,
> not accuracy estimates.

## Why

Live testing with Qwen3-1.7B (edit-list engine) returned `no_edits` for 15 of 17 real dictations: fillers
(`um`, `uh`, `like`, `you know`, `basically`) and the self-correction `Run the tests on Tuesday, no wait on
Wednesday.` all survived. It also damaged Czech: `Tohle je test diktování v češtině.` came back title-cased.

[S1-mini](https://huggingface.co/superwhisper/s1-mini) is a Qwen3-0.6B fine-tune that normalizes ASR output. It
removes fillers, resolves self-corrections and writes numbers as digits. It returns the full rewritten text, not
edits.

### Control line

I ran all 73 inputs through S1 with each styling. On the 34 inputs that are already clean, the raw rewrite
changed:

| styling | changed | how |
|---|---|---|
| **semi-formal** | 10/34 | final periods and commas, `!` → `.`, quotes around a mentioned word, ASR-error "fixes" (`Qan II` → `QANII`, `commit-m` → `commit`). The validator rejects all but the plain punctuation. |
| semi-casual | 32/34 | lowercases sentence starts and drops final periods, which damages already-cased ASR output |
| casual | 32/34 | as above, and also strips apostrophes |

Parakeet output arrives cased and punctuated, so every profile uses `semi-formal`. Chat keeps its "no added
final period" rule: the server removes a final `.` that S1 added to a chat text without end punctuation.
`lists` and `email` are not used yet.

## S1 engine: rewrite → edits → validator

1. Tokens are split on whitespace and aligned with `difflib.SequenceMatcher` on their words, ignoring case and
   punctuation.
2. Each changed stretch becomes a quoted edit. A deletion or insertion takes a neighbouring token along. A quote
   that is not unique grows by one token on each side. A stretch that contains a correction cue grows until it
   has the self-correction shape (kept words + 1–8 retracted words + cue + correction). Overlapping stretches
   merge.
3. The edits go through the existing validator (`resolve_edits`). The kind is whichever invariant the edit
   passes. The validator also checks protected spans and the global rules.
4. **All or nothing:** if one edit is rejected, the raw text is kept. The client validator checks the result again.

Validator changes (server and client):
- `number_format` is now checked: spoken numbers must become digits with the same value.
- `filler_removal` also allows `like`, `basically`, `literally`, `you know`, `kind of`, `sort of` and immediate
  repeats (`the the`).
- Punctuation edits may only add or remove `. , ; : ? ! ' ’ -`, and the result may not lose a `!`.
- Fillers may make up at most half of the words.
- A self-correction may drop protected spans inside the words it retracts.
- An edit may overlap a protected span only if the span text survives unchanged: `main.py` → `main.py.` passes,
  `3:30 pm` → `3:30pm` does not. A negation may only be re-cased at a sentence start.
- The client validator now checks self-corrections and number formats. It used to reject them.

The Qwen3 baseline exposed two holes in the first version of these changes, and both are now closed:
`There is no wait` → `There is No wait` was accepted, and so was `I mean it, this…` → `It, this…` (`I mean` as a
filler). S1 triggered neither.

Without the language guard, the 1.7B re-cased the Czech dictation (that is how the history recorded it). S1 left
it unchanged in the probe, but it is English-only, so the guard skips cleanup for both engines.

## Remaining S1 failures

- **All-or-nothing loses long dictations.** S1 handled both long real texts well, but each contained one change
  the validator cannot verify: deleting `I don't know` (a negation), `super whispered` → `Superwhisper`, or
  `like if um Hark could do` → `like Hark to do`. So the raw text was kept, fillers included. Applying only the
  edits that pass would recover most of the cleanup. Each such edit is safe by itself, but the result would mix
  S1's output with the raw text. That is not implemented.
- `No freaking way` → `No, freaking way`: a comma after a sentence-initial `No`. It passes every mechanical check.
- `3:30 pm` → `3:30pm` and `docker` → `Docker` touch protected spans, so the whole rewrite is dropped and the
  sentence-start capitalization is lost with it.
- Quotes around mentioned words (`delete the word "not"`) are rejected, by design.
- Garbled ASR (`So what um can I say them like foot wait what?`): S1 restructures it, the rewrite is rejected
  and the raw text stays. This is acceptable.

## Decision

**Default: S1-mini (`s1-mini-q4_k_m`, engine `s1`).** On the 44 cases it scores +11 exact over the 1.7B, with
8/8 self-corrections and 0 damage. It is 4× faster (p95 78 ms vs 331 ms) and 2.3× smaller (484 MB vs 1.1 GB).
It is the only model of the two that removes real fillers. `--cleanup-engine edits` (TOML `cleanup.engine`) keeps
the Qwen3 engine. `scripts/poc-up` picks the engine from the model key.

## Reproduce

```sh
scripts/fetch-llama && scripts/fetch-models s1-mini-q4_k_m qwen3-1.7b-q4_k_m
scripts/llama-up s1-mini-q4_k_m --port 8091 &
scripts/eval-cleanup --llm http://127.0.0.1:8091/v1 --model s1-mini-q4_k_m --engine s1 -v
scripts/eval-cleanup --llm http://127.0.0.1:8091/v1 --model s1-mini-q4_k_m --engine s1 \
  --data server/tests/data/cleanup_eval_real.jsonl -v
scripts/llama-up qwen3-1.7b-q4_k_m --port 8092 &
scripts/eval-cleanup --llm http://127.0.0.1:8092/v1 --model qwen3-1.7b-q4_k_m --engine edits -v
```
