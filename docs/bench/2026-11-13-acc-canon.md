## What changed and why

**Class 1, false identifiers: 10 → 0.** A match whose words are all everyday words (in the ~4900 most frequent
English words, wordfreq top 5000, `context/common_words.txt`; numbers count as everyday, single letters do not)
now needs evidence: a spoken separator in it (`underscore`, `dot`, `slash`…), a capital the recognizer wrote inside
it mid-sentence (`Session Store`, `window ID`), or identifier syntax around it (`called X`, `rename … X`,
`call it X`, `the hook X`, `X hook/function/field/flag/…`, `X returns`, `X is true/false/none`). Cleared:
real-001 `goBack`, real-005 `let_me`, real-007 and real-015 `each_other`, syn-084 `wait_for`, syn-091
`QuickShell`, syn-092 `last_text`/`one_line`, syn-093 `SessionStart`, syn-095 `mark_down`, syn-096
`TextField`/`ScreenText`. The recognizer's bias hits are not available to `canonicalize()` (the pipeline passes
text, words and terms only, and the gate replaces word confidences), so that form of evidence is not used.

True positives kept: every alias with one rarer word (`context snapshot`, `smart spacing`, `transcribe stream`,
`zero grad`, `confident anchor`, `hark server`, `use memo`, `boost min`/`boost max` after dropping written-only
abbreviations such as min/max from the list), and everyday ones with evidence (`use effect hook`, `field called
confident anchor`, `rename use session store`, `transcribe stream class`). **Lost (regressions), 4 critical
strings:** syn-018 `wait_final` ("why does wait final time out"), syn-024 `competition_key` ("a test for
competition key with"), syn-033 `useEffect` ("fetching in a use effect"), syn-021 `check_focus` (said "is false",
heard "is paused", so the cue is gone). These are everyday-word identifiers said with no cue; the trade is
deliberate (a false identifier changes the sentence, a missed one still reads right).

**Class 2, spoken forms.** `aliases.LEXICON` holds names not said as spelled (hyprland, hyprctl, ctl, kubectl,
systemctl, journalctl, ghostty, basedpyright, pyright, pytest, sqlite, postgres, qwen, wav, uv, tmux, nvim, zsh,
nginx, src, …), applied to a whole run (`SQLite`) and to each word (`ctl` in `hark ctl`). Also: versions with
"point" (`0.6` → "zero point six"), an optional spoken colon (`node:22-alpine` → "node twenty two alpine"), leading
prefixes said symbol by symbol (`~/.kube/config` → "tilde slash dot kube slash config", `@/lib/utils`,
`$XDG_RUNTIME_DIR` → "dollar …"). Matching normalizes both sides: letters/digits split (`S1` = "s 1"), number words
are digits ("twenty two" = 22), "point"/"dot" between numbers dropped. A match right after a spoken separator is
skipped, so a spoken path is rewritten whole or not at all. One-word aliases count when they are no English word or
a hand-picked lexicon form (`ghosty` → `Ghostty`, `hyperland` → `Hyprland`). A command term gets a case-only
rewrite mid-sentence ("to Hark history list"). `canonicalize()` also derives the current spoken forms, so replayed
shortlists (eval, `hark retry`) get them. Fixed: syn-036 `hark history`, syn-046 and syn-050 (no more "tilde slash
dot ~/.kube/config" / "at slash @/lib/utils"), syn-055 `node:22-alpine`, syn-063 `Hyprland`, syn-065 `SQLite`,
syn-077 `hark ctl paste-last`, syn-078 `Ghostty`, syn-087 `S1-mini` and `Qwen3`. Still missed: syn-075, where
the gate wrote "Hyper LAN" and "HyperControl" in one word (the lexicon has "hyper control"; an earlier run had
"Hyper-Control", which does become `hyprctl`).

**Class 5, spoken symbols** (`symbols.py`, terminal profile): recognizer-joined `up-d`/`pytest-k` and `dash-fix`
once a command that is no everyday word (docker, uv, ruff; not add/make) was said in the sentence;
`dash-dash fix` → `--fix`; `dash d` after any non-function word in such a sentence; `localhost:8000 slash health`
and `localhost colon 8000` → `localhost:8000/health`; a function word is never the first part of a path
(`to /data/models`); `chmod plus x` → `chmod +x`; `user underscore id` → `user_id` (not after/before function
words: "with an underscore" stays); number words after issue/PR/port/ticket → digits (`PR 437`, `port 8080`,
`port 50051`); `zero comma one` / `0, comma one` → `0,1`; a capitalized command followed by one of its
subcommands is lower-cased (`Git status`, `Hark history`). Fixed: syn-031, syn-047, syn-053, syn-082 (`0,1`),
syn-037 `--fix`, syn-043 `/data/models`, syn-045 `chmod +x`; syn-048 `feat/eval-set` now survives.

**Terminal base vocabulary (class 4).** `words.with_terminal_commands(terms, max_terms)` appends git, uv, npm,
pnpm, docker, kubectl, cargo, journalctl, systemctl, uvx (weight 0.3, spoken forms from the lexicon) in free slots,
taking at most a quarter of a full list from its weakest terms. **It has no caller yet**: the hook belongs in
`pipeline._run_collect` (not this branch's file). Measured with this uncommitted patch after the `[[words]]` merge:

```python
if self.svc.cfg.profile(self.svc.cfg.profile_for(snap.focus)).terminal:
    snap = replace(snap, terms=with_terminal_commands(snap.terms, cfg.max_terms))
```

Effect: syn-010 "Cube control get pods dash n staging" → `kubectl get pods -n staging.`; syn-080 "B N B M R" →
"B npm R" (still wrong). "Get status" / "Get push" (syn-005, syn-041) are not fixed: the boost on `git` does not win
there.

## Not measured / open

- The eval replays saved shortlists, so the lexicon and the new spoken forms reach canonicalization but **not the
  bias list** (asr.bias_list reads the saved `Term.spoken`). Live dictations get them through `rank` →
  `spoken_forms`. Recognition gains (e.g. "Hyper LAN", "harp control", "rough check", "based pie write") are
  unmeasured; to measure them, the replay would have to re-derive aliases, or the set's context.json be rebuilt.
- Cleanup now sees ordinary phrases where the identifier was meant but not canonicalized and sometimes capitalizes
  them (syn-021 "check focus" → "Check Focus").
- Other traps of the same shape on real speech (identifiers made of everyday words with no cue) now stay prose.
  Measure TP vs FP again when the set has more of both.
