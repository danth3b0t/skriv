# ux-wave2: eval before/after (2026-11-13)

Branch `ux-wave2`, items 1-6 of the wave-2 UX gap list. These are delivery and UX changes: start cue, release
latency, `hark words`, the 5 min length limit, `hark last --raw`, and the no-speech mic diagnosis. None of them
changes recognition, gating, canonicalization or cleanup for an eval clip:

- The eval feeds audio straight into `Utterance`. The start cue (now never masked) and `audio.max_ms` (now
  pre-roll included, never past the server's 300 s) live in the daemon.
- The repository words list (`<repo>/.hark/words.toml`) would apply to a clip whose recorded `repo_root` has one.
  No checkout on this machine has one.

So any difference between the runs is run-to-run noise.

Command: `uv run hark --config docs/bench/eval-baseline/baseline.toml eval run --set eval/dev-v1 --report
/tmp/ux-wave2-{before,after}.json` against the shared server (:50051) and llama-server (:8080).

14 clips changed text. All of them are noise from the shared stack:

- Recognition: real-015 (before) and syn-005 (after) came back as `ÌÌÌ…` / `<unk>…` garbage from the shared
  server. Each happened in only one run.
- Cleanup: real-004, real-012, real-014, real-016, real-018, real-019, syn-067, syn-073, syn-074, syn-075,
  syn-076 and syn-077 got different rewrites, or a rejected vs applied outcome, from the shared llama-server,
  which other branches were also using.

syn-067 passing and the latency drop come from the same noise: the llama-server was busy during the "before" run.

In the eval, release->paste starts when `finish()` is called, because there is no key. It is therefore close to
key-up->paste. In the daemon it starts at the key release, before the recovery copy and the wait for the key-down
context.

Unreviewed clips that now look correct: none that this branch caused, so none are listed for acceptance.
