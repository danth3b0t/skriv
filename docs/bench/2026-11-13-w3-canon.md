## What changed, by item

1. **Replay fidelity** (`retry.load_snapshot`, used by `hark retry` and `hark eval`). Each replayed term's spoken
   forms are now `spoken_forms()` first, then the stored forms it lacks. A live dictation gets the same from `rank`.
   The server keeps the first 8 aliases, so today's forms win. Alone, this changed 10 clips (the earlier probe
   changed 9). Two of them came from runs without an anchor. The others:
   - **syn-078 FAIL → accepted**: "Harp Control toggle" → "hark control toggle" → `hark ctl toggle`.
   - syn-029 "baste pie write" → `basedpyright` (still FAIL on `read_wav`/`write_wav`).
   - syn-037 "baste Pyrig" → "based pi".
   - syn-044 "journal control-user" → "journal control-dash user".
   - syn-063 "VAR" → "var" (said "bar").
   - syn-075 "hyper control" → `hyprctl`. "hyper land" still goes to "Hyper LAN" (gate `inflection`, not my file).
   - syn-079 "diet" → "di".
   - syn-007 "pyTest-k" → "pie test-k". Fixed by item 2.
2. **canon.py**
   - Recognizer hyphens: a chunk joined like `word-word` also starts and ends matches at each hyphen.
     **syn-007**: "pie test-k" → `pytest-k` → (symbols) `pytest -k`, **FAIL → correct**. syn-044: "journal
     control-dash" → `journalctl-dash` (still FAIL: "dash u hark" was heard as "UROC").
   - "journal control" is two everyday words, so it still needs evidence. New evidence: a flag right after a COMMAND
     term (the recognizer joined it with a hyphen, or "dash" follows). "keep journal control tight" stays prose.
   - Case: the recognizer's inner capital no longer blocks a case-only rewrite (`pyTest` → `pytest`). A single token
     that is a shortlist spelling but for inner capitals takes the shortlist case, without a trailing `()`.
     **syn-076** `model.Train` → `model.train` (**FAIL → accepted**). A sentence capital (`Optimizer`) and an
     acronym (`API`) stay as written.
   - Bias hits as evidence: the pipeline passes the recognizer's hits to `canonicalize(hits=...)` as
     (canonical, start_ms, end_ms). They are evidence only when they overlap the match's timed words and belong to
     the same term. **I ship APPLIED hits only** (the unbiased anchor did not have the words, the bias put them
     there). Reason: the server derives hits by matching text, so every alias in the output is a hit. The probe that
     took every hit fixed syn-018, syn-024, syn-029 and syn-033. It also wrote 4 false identifiers in 3 trap clips:
     syn-084 `wait_for the`, syn-091 `QuickShell`, syn-096 `TextField`/`ScreenText` (0/29 → 4/29). The logged hits
     show why. `wait_final`, `competition_key`, `useEffect` and the traps `QuickShell`, `TextField`, `wait_for` are
     all `ALREADY_IN_ANCHOR`, so the hit data cannot tell them apart. Of the 116 hits in the set, 34 are APPLIED.
     With APPLIED only, 0 clips change in this set. The 3 everyday-word misses (class 1) are still misses.
   - Spoken separators: an alias with ≥ 2 spoken separators matches when exactly one other word is a close
     mishearing (same first letter, difflib ratio ≥ 0.75, ≥ 3 letters) and only one term fits. **syn-043**
     "hark underscore models underscore diar" → `HARK_MODELS_DIR` (**FAIL → correct**). Two misheard words, a far
     one ("door") or a single separator do not match. Note: the phrase has two separators, not three as the brief
     said.
3. **symbols.py**: `dash-<flag>` becomes the flag without a recognized command when the flag is on the shortlist
   (the pipeline passes the FLAG terms). **syn-037 is not fixed**: `--fix` is not on that clip's shortlist (it has no
   FLAG term), so this rule cannot fire there. The only way to get `--fix` there would be the old "any dash-word"
   rule without a command, and that one was rejected as too loose (`dash-free`).
4. **Terminal profile "Get" + git subcommand** at the start of the text → `git`, when the subcommand ends the
   text or a clause, or a flag, `origin`/`upstream`/`main`/`master`/`HEAD` follows. **syn-005** "Get status." →
   `git status.` (**FAIL → correct**). **syn-041** "Get push --force-with-lease" → `git push …` (still rejected:
   "force bush main" is recognition). "Get commit messages from last week", "Get status of the build" and "Then get
   status" stay prose.
5. See the spoken-separators rule in item 2.
