# Bench: cleanup fidelity, per sentence, invented identifiers, dropped imperatives (2026-11-13)

Triage class C of the [merged eval](2026-11-13-eval-merged.md) and the open points of
[cleanup-fidelity](2026-11-13-cleanup-fidelity.md): two rewrites passed the fidelity check but were not faithful
(syn-029, syn-033), and one bad change in a long dictation kept every filler of it (all or nothing).

## Change (`client/src/hark_client/fidelity.py`, `cleanup.py`)

- **Invented identifiers.** A rewrite fails if it adds a camelCase, PascalCase, snake_case or dotted identifier that
  is not in the input (in any case) and not protected (the shortlist canonicals in the input or the rewrite, the
  input's code-like tokens). Exceptions: adjacent input words run together exactly as written (`Hyper LAN` →
  `HyperLAN`, a name the speaker already cased), or with their spoken separators (`model dot train` →
  `model.train`, `user underscore id` → `user_id`). `read wave` → `ReadWave` fails. The old content rule let it
  through, because merges do not count as added content.
- **Dropped opening verb.** A rewrite fails if it drops the first word of a sentence that is a content word not set
  off by a comma (fillers and discourse words skipped). In practice that is the verb of an imperative: `Use useQuery
  …` → `useQuery …`. The words are counted, not just checked for presence, so the "use" in "a use effect" later in
  the sentence does not cover for it. A restart (`After after I've done after we're done` and `m men`, where the
  word comes back within four words) and a one-word sentence (`etc.`) do not count.
- **Per sentence.** `fidelity.accept` runs the whole check first. If the check fails, it splits input and rewrite
  into sentences and aligns them in order with a small DP. The alignment allows 1:1, joins and splits up to 3:1 and
  1:3, and dropped or added sentences, and minimises the words found on one side only; a join or split costs one
  word more. Each rewritten group that passes `check` against its input sentences is kept. Every other group keeps
  the input's sentences, and an added sentence is dropped. If no group passes, or if the mix fails the whole check
  (a safety net for strings moved across sentences), the input stays. Self-corrections still work: the cue's group
  is checked with the retraction rule (`Set it to 3 seconds. Sorry, 5 seconds.` → `Set it to 5 seconds.` is a
  2:1 group).
- **Outcome interface unchanged.** A partial rewrite is `status = applied`, with `reason = "kept N of M sentences as
  said: <first refused rule>"`. The indicator, `hark history` and the eval treat it as applied. `pipeline.py` is
  untouched. `scripts/eval_cleanup.py` reports these as `partly`.
- **Content words (point 4).** I measured every accepted rewrite in this run, in the earlier cleanup-fidelity
  reports and in the three cleanup sets for function-word substitutions such as `can` → `could`, `will` →
  `would`, `do` → `did` or pronoun swaps: there are none. The only function words that went were fillers (`you
  know`, `I mean`), `gonna` → `going to` and self-corrections. No stem miss showed up either. The one fix: a
  contraction of a function word (`it's`, `let's`) no longer counts as the content word `it`. The new
  opening-verb rule exposed this on real-006 (`it's it was` → `It was`). The stem list and `len // 8` are
  unchanged.

## Open / risky

- The per-sentence mix checks each group on its own, with a whole-text check as a safety net. Content moved between
  sentences can still duplicate a word, because the content check uses sets. The net catches this for protected
  strings, negations and numbers, but not for plain words.
- The sentence split is punctuation only (`etc.`, `e.g.` split too). The alignment absorbs this, as on r-filler-5.
- The opening-verb rule fails a few rewrites that were fine before, for example `Make sure X` → `Ensure X`. That
  case is not in the sets.
- The invented-identifier rule accepts a merge of words cased as spoken (`Check Focus` → `CheckFocus`). A
  protected-string check still catches syn-021's `smart_spacing` → `SmartSpacing`.
- Recognition and gate output on the shared :50051 varied between the two runs (6 clips), so compare end-to-end
  numbers only together with the replay above.
